## 1. Выбранная тема и обоснование

**Вариант А — собственная тема:** мобильный **NEO Tracker** — сближения астероидов с Землёй
по данным NASA NeoWs.

Почему эта тема:

- Это прямое продолжение Лаб 3 (настольный NASA NEO Tracker), поэтому предметная область
  уже понятна, и можно сосредоточиться на новом языке и мобильной платформе.
- У NASA NeoWs есть **исторические данные за любую дату**, поэтому экраны «Неделя» и «Месяц»
  работают сразу после установки — не нужно неделями копить данные локально.
- Показатель для экранов сравнения естественный и меняется день ото дня:
  **число сближений за день** (основной). Дополнительно можно переключиться на
  **число потенциально опасных** и **минимальное расстояние промаха** (млн км).

Базовая функциональность: поиск сближений за дату (как в Лаб 3) + новые экраны сравнения
за 7 и 30 дней с графиком, минимумом, максимумом, средним, изменением (абс. и %) и явной
тенденцией (рост / падение / без изменений).

## 3. Источник исторических данных и его ограничения

**Источник:** NASA NeoWs, метод `GET /neo/rest/v1/feed?start_date=…&end_date=…&api_key=…`.

**Как получаем период:** `feed` отдаёт максимум **7 дней за запрос**, поэтому:

- «Неделя» (7 дней, включая сегодня) — **1 запрос**;
- «Месяц» (30 дней) — **5 запросов**: 7 + 7 + 7 + 7 + 2 дня (`splitRange` в `date_utils.dart`).

Все полученные дни сохраняются в локальный кэш. Итог — комбинация подходов:
**API с историческими данными + накопление в локальной базе**.

**Ограничения и как они учтены:**

| Ограничение | Решение |
|---|---|
| `DEMO_KEY`: около 30 запросов в час и 50 в сутки с одного IP | Экраны создаются только при первом открытии вкладки; в настройках можно указать бесплатный личный ключ (до 1000 запросов/час); после HTTP 429 остальные куски не запрашиваются |
| Максимум 7 дней за запрос | Разбиение периода на куски |
| Часть кусков может не загрузиться | Эти дни берутся из кэша; если их нет и там — экран прямо пишет, за сколько и какие дни нет данных, и считает статистику по оставшимся (пропуски **не** превращаются в нули) |
| Нет сети совсем | Показываются сохранённые данные с датой актуальности; если сохранённых нет — понятная ошибка и кнопка «Повторить» |
| Данные NeoWs — расчётные сближения по орбитам, а не «наблюдения за день» | Для задачи сравнения это плюс: данные за прошлые дни стабильны и доступны сразу |
| Размер кэша | Храним не больше 120 дней, старые вытесняются |

## 5. Что ИИ сгенерировал корректно, а где ошибся

**Корректно с первого раза:**

- Разбор ответа NeoWs с учётом того, что NASA присылает числа строками (`"8.51"`), и с заменой
  битых/отрицательных значений на «нет данных» вместо нуля.
- Разбиение месяца на 5 запросов и сшивание результата с кэшем.
- Формулы статистики и тесты к ним, включая крайние случаи (пустой набор, старт с нуля,
  одна точка).

**Ошибки ИИ и исправления (видны в истории коммитов):**

| Ошибка | Как обнаружена | Исправление |
|---|---|---|
| Шаблон Android взят из самой свежей ветки Flutter — там флаги под AGP 9 (`android.newDsl`, `builtInKotlin`), которые старые версии Flutter не понимают | Сверка шаблона перед коммитом | Использован проверенный шаблон под AGP 8 / Kotlin; в README — команда `flutter create .` для пересоздания обвязки под свою версию |
| В графике при ровной линии переменной типа `double` присваивалось значение типа `num` (`cond ? 0 : lo - 1`) — ошибка компиляции | Самопроверка кода | Явно `0.0` и упрощённая логика |
| Все 4 вкладки в `IndexedStack` создавались сразу → при старте уходило 7 запросов (1 + 1 + 5) и съедало лимит `DEMO_KEY` | Подсчёт запросов при старте | Ленивое создание вкладок (коммит `fix(ui): create period screens lazily…`) |
| Обрабатывались только `SocketException` и `ClientException`; ошибка TLS (`HandshakeException`) прошла бы мимо и экран завис бы без сообщения | При написании тестов на ошибки сети | Общий перехват транспортных исключений + тест (`fix(data): map any transport exception…`) |
| Тест рассчитывал на точный текст сообщения, хотя `MockClient` может обернуть `SocketException` в `ClientException` | Ревью тестов | Тест проверяет факт показа кэша и наличие предупреждения, а не конкретную формулировку |
| Среда ИИ не имела доступа к Flutter SDK и pub.dev, поэтому код писался **без компиляции** | — | Первый `flutter test` и запуск выполнены на машине студента (см. раздел 7) |

## 6. Насколько сложнее или проще работать с ИИ на новом языке

Главный вывод: **ИИ снимает барьер синтаксиса, но не снимает необходимость понимать платформу.**

- **Проще.** На Dart/Flutter я до этого писал мало, но генерация кода почти не замедлилась
  по сравнению с Python: ИИ одинаково уверенно пишет на обоих языках. Dart по синтаксису
  близок к Java, которую я знаю, поэтому сгенерированный код читается легко — `class`,
  `final`, типы, `Future`/`async` понятны без справочника. Новые для меня вещи Dart 3
  (records `(DateTime, DateTime)`, `switch`-выражения, сопоставление с образцом) ИИ
  применил уместно, а я разобрался в них по готовым примерам быстрее, чем по документации.
- **Сложнее.** Самые трудные места оказались не в языке, а в **окружении**: версии
  Gradle/AGP в Android-обвязке, разрешение `INTERNET` для release-сборки, отличие
  кэширования на телефоне (`SharedPreferences`) от файла на диске. Здесь ИИ ошибается
  чаще — он знает много версий одновременно и может взять «слишком новый» шаблон.
  На знакомом Python такую ошибку я бы заметил сразу, на новом стеке — только при сборке.
- **Проверка стала важнее.** В незнакомом языке я хуже вижу ошибку глазами (пример —
  `num` vs `double` в графике), поэтому основным способом контроля стали тесты и запуск,
  а не чтение кода. Это совпадает с требованиями лабораторной: тесты на парсер и статистику
  ловят именно те ошибки, которые на новом языке легко пропустить.
- **Итог:** навык работы с ИИ действительно не привязан к языку — постановка задачи,
  разбиение на этапы, ревью и тесты переносятся один в один. Привязанным оказывается
  знание платформы и инструментов сборки: без него ИИ-код на новом языке можно получить
  быстро, а запустить — нет.
